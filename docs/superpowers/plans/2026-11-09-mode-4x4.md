# Mode 4x4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a match format choice "6 x 6 / 4 x 4". In 4x4 there are 4 fixed court slots (R4→zone 4, Central→3, Pointu→2, Passeur→6), no rotation and no libero. 6x6 behaves exactly as today.

**Architecture:** Store a single `format: MatchFormat` in `MatchState`, set via `SETUP_MATCH`. A pure config module, `src/data/matchFormat.ts`, maps each format to its court size, slots, grids, `rotation` flag and `libero` flag. Every screen and reducer branch reads that config instead of hardcoded `6`. The reducer also blocks rotation and libero actions in 4x4, so no forgotten UI path can trigger them.

**Tech Stack:** React Native (Expo), TypeScript strict, Context API + useReducer, StyleSheet.

**Spec:** `docs/superpowers/specs/2026-11-09-mode-4x4-design.md`

**Verification note:** This repo has **no unit-test runner** (no jest/vitest, no `test` script), and adding one is out of scope. Every task is gated by `npx tsc --noEmit` (expected: no output, exit 0) plus the manual check listed in the task. Run it with `npx expo start --web` or on a device.

## Global Constraints

- TypeScript strict: no `any`, no `!` non-null assertion; use early returns.
- Prefer `type` over `interface`. Props are typed explicitly.
- `StyleSheet.create` only, with tokens from `src/constants/theme.ts` (`COLORS`, `SPACING`, `FONT_SIZE`, `RADIUS`).
- Single source of truth: `format` lives only in `MatchState`. Everything else is derived from `FORMAT_CONFIG[format]`, never copied into local state, and no `useEffect` syncs it.
- **No backend change.** Postes sent stay within `R4 | Central | Passeur | Pointu`; positions and zones stay within 1–6.
- 6x6 behaviour must be unchanged: rotation, libero, 2-2-1-1 composition, "5-1" tab.
- UI copy is in French, matching the existing screens.

## Review Focus

1. **A 4x4 point won on the opponent's serve (side-out)** must not move any player. `opponentServing` must still flip to `false`, and UNDO must restore the score without touching positions. Test: Task 2, step 4, scenario A.
2. **Restoring the previous set's layout:** in 4x4, set 2 must start from set 1's 4-slot layout, not reset because the map has 4 entries instead of 6. Test: Task 4, step 4, scenario C.
3. **Substitution in 4x4:** the incoming player keeps the outgoing player's zone and poste, the 6-substitutions-per-set limit still applies, and no libero exclusion bug hides bench players. Test: Task 5, step 4, scenario E.
4. **Positions tab mid-set:** swapping two 4x4 cells also swaps postes, so the poste always matches its zone. Test: Task 6, step 3, scenario F.
5. **Back-navigation:** going back from team selection to match setup and starting a new match must restore format to `'6x6'` by default. In a 6x6 match after a 4x4 one, the 6x6 grid and rotation must be back. Test: Task 3, step 3, scenario B.

**Interfaces:**
- Produces:
  ```ts
  export type MatchFormat = '6x6' | '4x4';
  export type FieldRole = 'R4' | 'Central' | 'Passeur' | 'Pointu';
  export type FormatConfig = {
    label: string;                         // '6 x 6' | '4 x 4'
    courtSize: number;                     // 6 | 4
    slots: number[];                       // zones used, in initial-fill order
    slotRoles: Partial<Record<number, FieldRole>>; // zone → fixed poste ({} in 6x6)
    gridRows: (number | null)[][];         // SetSetup grid, top→bottom, null = spacer
    oppFillOrder: number[];                // opponent zones filled by jerseys 1..n
    rotation: boolean;
    libero: boolean;
  };
  export const FORMAT_CONFIG: Record<MatchFormat, FormatConfig>;
  ```
  - `MatchState.format: MatchFormat`
  - `actions.setupMatch(payload: { matchName: string; isHome: boolean; format: MatchFormat })`
